# プロンプト改善・デバッグ認証の本番導入（2026-10-11）

ユーザーの「本番環境への実装を行い、依然として残る問題をレポートと共にissue化して」という指示に基づき、試験済みのボイス例・口調調整、共有記憶の根拠を区別する共通指示、無料版APIの認証付きデバッグ通信を本番へ反映した。

## 反映内容と範囲

- 通常版・無料版: ホシノ、ヒナ、ユウカの短いボイス抜粋と口調指定を採用。共通の根拠・共有記憶の指示は全生徒へ適用。
- 無料版: Workerの秘密キー `DEBUG_TOKEN` とリクエストヘッダー `X-Debug-Token` が一致する通信だけ、分単位・利用元別の日次・全体の日次カウンターをスキップする。入力検査、対応モデル、出力上限、Groq自身の制限は維持。
- 直近の別変更も維持: 通常利用は5回/分、利用元別60回/日、全体800回/日。Groq側で429または5xxなら別モデルへ切り替える既存処理も維持した。
- 追加点検・修正は検証用のまま。誤検知と修正失敗があるため、アプリの送信処理には接続していない。会話履歴の削除や既存メッセージの書き換えは行っていない。

## 確認済みの結果

- 通常版: 26ファイル・385件のテスト、型チェック、ビルド成功。公開コードは `a851c47355e512ab5cdc562ec74ba2e6f4e61fd3`。GitHub Pagesの[本番デプロイ](https://github.com/hirarara74/momotalk_AI/actions/runs/38137059418)は成功。
- 無料版: 28ファイル・401件のテスト、型チェック、ビルド成功。デバッグ判定を反転するとテストが失敗し、元へ戻すとプロキシの全テストが成功することも確認。公開コードは `28cb798`。
- 無料版Worker `e349e103-f9bb-40cf-9092-1ba7823fc375` を100%へデプロイした。試験時の0%版指定は、本番のデバッグ利用には不要。
- [通常版](https://hirarara74.github.io/momotalk_AI/)・[無料版](https://momotalk-ai-free.momotalk-ai.workers.dev/)のページとJavaScriptは200。公開JavaScriptに共有記憶の指示と新しいボイス例が入っていることを確認。無料版の公開JavaScriptはローカルで検証したビルドとSHA-256が一致。通常版はCIで作成したビルドのためローカルとのバイト一致は確認していない。
- 公開JavaScriptにデバッグ秘密キーが含まれていないことを確認。秘密キーはGit対象外のローカルファイルとWorkerのSecretで保持。
- 本番APIで誤ったトークン403、未対応モデル400、40,001文字の入力413、正しいデバッグ認証200、トークンなしの通常リクエスト200を確認した。バージョン指定ヘッダーは使用していない。
- 既存の大きなbundleとViteの非推奨APIに関する警告は残る。ビルドエラーはなかった。

## 残る問題

少数の合成会話による試験では、捏造が残る返答は対策前9/12件、共通指示追加後7/12件だった。**本番に導入したのは、この指示追加までである。** 過去のAI発言だけを根拠に贈り物の場所・飲んだ経験・架空の行事を語る問題は残る。

検証用の追加点検では7件すべてを検出したが、4件しか解消せず、最終返答には3/12件の捏造が残った。誤りのない11候補中2件を誤検知した。正しい缶の色を曖昧にする、将来の提案を不必要に修正する、先生を責めるような口調になる副作用がある。会話内の実際の約束を保持する追加の3条件はすべて保持できた。

ボイス例と周辺指示の調整には改善傾向があったが、少数例の定性的な評価であり、公式音声との照合は未実施。対象3人以外の例は創作のままで、不自然な自称や口調も完全には解消していない。長い履歴、他言語、他モデルへの一般化は未確認。

## 切り戻しと未確認事項

APIの障害が出た場合は、Cloudflareの以前の稼働バージョンへ戻す。デバッグ解除を無効化する場合はSecretを削除または交換する。プロンプトの切り戻しは対象2ファイルの変更を戻すコミットを両リポジトリへ反映して再デプロイする。共有ボタンなどの別作業は戻さない。

今回は公開ファイル・API・デプロイ状態を確認した。個人の会話履歴、ブラウザでの手操作による全会話導線、長期の稼働状況、捏造の完全防止は確認していない。
